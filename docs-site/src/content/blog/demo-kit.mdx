This is a test page for the blog engine, not a finished guide. It brings the article components together so we can check the reading width, captions, keyboard navigation and system appearance before publishing real articles. Every reading below comes from simulated data.

## Dashboard at full size

The dashboard needs room for its navigation and charts. On a wide screen it expands beyond the text column. On a phone, a GPU card takes its place and the link opens the dashboard in a separate tab. The example remains readable without shrinking the app.

<ArticleDemo

## A route with parameters

This second frame opens the processes page with GPU columns selected. Its route includes a query string, kept separate from the parameters on the demo document itself. Use this section to check that navigation survives copying a demo link.

## An agent session

This scripted exchange uses invented output. It checks that commands remain selectable and the finished transcript is available without JavaScript.

<AgentSession
  client:visible
  request="Check what is using CPU on this Mac."
  steps={[
    {
      command: "statglass now",
      output: "CPU 18.4%  GPU 12.0%  Memory 14.2 GiB",
    },
    {
      command: "statglass top --by cpu --limit 5",
      output:
        "Process        CPU\nSafari         8.2%\nWindowServer   4.1%\nTerminal       2.0%\nFinder         1.2%\nStatGlass      0.4%",
    },
  ]}
  answer="Safari is the busiest process in this sample. Total CPU usage is still low."
  caption="An example session with simulated command output."
/>

## Markdown checks

The prose flag --since 1h and inline code `--since 1h` must keep their two ASCII hyphens.

```sh title="Read recent history"
statglass history --since 1h
```
